# 需求文档

Waddle 的每一次改动都先有一份需求，再实现，最后验收。**不直接开始实现。**

## 流程

```
提需求（Claude） ──► 实现（Codex 等） ──► 验收（Claude）
      ▲                                      │
      └──────── 没做到：再提一份需求 ◄─────────┘
```

1. **提需求**：看项目现在的样子，写「做什么、为什么、做到什么样」。只写需求，不写怎么实现。
2. **实现**：实现者自己决定怎么做，做完在文档里写「实现说明」：做了什么、怎么试用。
3. **验收**：按「怎样算做好」看结果，写进「验收记录」。验收时不改代码。
4. 没做到：**不改旧文档**，再提一份新需求，「上一份」指向旧文档，只写没做到的部分。

一份需求可以分多个阶段。实现者每做完一个阶段就停下，把状态写成「已实现（阶段 N）」；验收通过后状态改成「待实现（阶段 N+1）」，全部阶段通过才是「验收通过」。

Claude 侧用 `/dev` skill（[.claude/skills/dev/SKILL.md](../../.claude/skills/dev/SKILL.md)），实现者的规则在 [AGENTS.md](../../AGENTS.md)。

## 文件命名

`YYYY-MM-DD-NN-简短英文名.md`，NN 是当天的序号，从 01 开始。例：`2026-11-20-01-codex-approvals.md`。

新文档从 [_template.md](_template.md) 复制。

## 状态

| 状态 | 含义 | 谁改 |
|---|---|---|
| 待实现 | 需求写好，等实现。这个阶段需求还能改 | 提需求的人 |
| 已实现 | 实现完成，实现说明已写 | 实现者 |
| 验收通过 | 「怎样算做好」都做到了 | 验收者 |
| 验收不通过 | 有没做到的，已另提新需求 | 验收者 |

进入「已实现」后，需求部分不再改。
