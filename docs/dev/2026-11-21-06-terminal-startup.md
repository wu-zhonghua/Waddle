# 新开的终端不再打出 bind 报错

- 状态：待实现
- 日期：2026-11-21
- 上一份：[2026-11-19-02-terminal-ai-command](2026-11-19-02-terminal-ai-command.md)
- 涉及：安卓

## 现在的样子

2026-11-19-02 验收时看到：安卓上每开一个终端（启动时的终端、抽屉里新建的、从文件夹「打开终端」的），提示符前面都会先出现两行 `bash: bind: 'vi-insertion': invalid keymap name`。这是那份需求给终端加的 Codex 命令集成带来的，第一版终端没有。用户每次打开终端都会先看到报错，以为哪里坏了。

截图：[启动时的终端](screenshots/2026-11-21-acceptance-01-terminal-start.png)、[从文件夹打开的终端](screenshots/2026-11-21-acceptance-06-terminal-in-phone-folder.png)。

## 要做什么

新开的终端干干净净：第一行就是提示符，没有 Waddle 自己带来的报错或警告。「问 Codex 写命令」以及生成后回车执行，在 Emacs 和 Vi 两种输入模式下都照常能用。

## 不做

- 不改「问 Codex 写命令」的界面和流程，不改提示符的样式。
- 用户自己在 `.waddlerc` 里写错的配置，报错照常显示，不替用户藏起来。
- 桌面端。

## 怎样算做好

- 在安卓模拟器上，启动时的终端、抽屉「＋ 新建终端」、从文件夹「打开终端」这三种方式开的终端，第一屏都没有 `bind` 之类的报错，直接是提示符。
- 在 Fold7 上新开终端，同样没有报错。
- 默认（Emacs）模式和 `set -o vi` 之后，用「问 Codex 写命令」生成、编辑、回车执行都只执行一次，结果出现在原会话。
- 用户在 `.waddlerc` 里故意写一条错误的命令，新终端仍然显示这条报错。
- Android 构建、lint 和终端相关的设备测试通过；GitHub 上 Android、Desktop checks 通过。
