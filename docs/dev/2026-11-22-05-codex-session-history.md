# Codex 对话页选择历史 session，恢复消息并在原目录继续聊

- 状态：已实现
- 日期：2026-11-22
- 上一份：[2026-11-22-04-bundled-agents-and-accounts](2026-11-22-04-bundled-agents-and-accounts.md)（阶段 1 补充）
- 涉及：安卓

## 现在的样子

国际版已经能从终端打开 Codex 对话，抽屉可切换正在进行的对话。但关闭对话或重启应用后，界面没有历史 session 入口；保存在私有 `.codex` 的旧对话只能用 CLI 恢复。

## 要做什么

- 在 Codex 对话页增加「历史对话」入口，列出本机保存的历史 session，包括旧版 Waddle 和原版 CLI 的对话。
- 每项显示标题（没有标题时显示首条消息摘要）、最近更新时间和工作目录；按最近更新排列，能继续加载更早的记录。
- 选择后恢复原 session 和历史消息，继续聊天；始终使用该 session 原来的工作目录，不用打开入口时的终端目录替换。
- 已在 Waddle 打开的 session 直接切回，不重复创建，不打断其他进行中的对话或丢弃草稿。原目录不存在、没有访问权限或恢复失败时说明原因，不悄悄换目录。
- 抽屉继续只放正在进行的对话；国内版不出现 Codex 入口。

## 不做

- 历史对话的删除、重命名、归档管理，以及跨设备同步。
- Claude Code、Antigravity 或 01 的多步任务阶段。
- 改变原版 CLI 的历史选择界面。

## 怎样算做好

- Fold7 对话页能打开历史列表，看到标题、更新时间、目录，并能加载较早记录。
- 从另一目录打开 Codex 后选择旧 session，看到旧消息；使用真机已有登录继续一次真实对话，确认仍是同一 session，工作目录保持原值。
- 在两段对话间切换、再次选择已打开的 session，消息和草稿仍在，不出现重复的活动对话。
- 原目录缺失时恢复失败有提示，其他对话、文件和登录不受影响。
- 安卓构建及相关回归测试通过。Fold7 只对用户 0 覆盖安装，不卸载主应用或清除数据；安装前后核对用户文件，测试后删除测试应用并打开主应用。

## 实现说明（实现者填写）

### 做了什么

- 国际版 Codex 对话页顶部新增「历史对话」。通过内嵌 Codex 0.170.0 的 `thread/list` 读取本机未归档记录，不按当前终端目录或模型服务商过滤；包含 CLI、app-server 等交互来源，不列子代理临时会话。每页 30 条，按更新时间倒序，显示名称/首条消息摘要、时间、完整工作目录，可刷新和加载更早记录。
- 选择后打开独立活动面板，保留原面板和草稿；若该 session 已在 Waddle 打开则直接切回，包含正在恢复的面板，避免重复。仍遵守最多 8 个活动对话的限制。
- 恢复时先 `thread/read` 获取权威 cwd 并校验目录权限，再 `thread/resume` 同一个 ID；不会用列表缓存或入口终端的目录替换。消息和图片/文件查看沿用已有渲染；后续 `turn/start` 使用恢复后的目录。原目录缺失时显示错误，禁用发送，提供「重试恢复」，不改动其他面板。
- 历史查询的加载和错误状态独立于聊天任务；查询失败不会取消任务、清除审批或把任务误标为空闲。抽屉仍只列活动对话，国内版无 Codex 入口。没有实现阶段 2、3，也没有修改桌面代码。

### 怎么试用

Fold7 主用户 0 已覆盖安装更新后的 `0.6.0-international`。在终端敲 `codex --waddle-chat`，点顶部「历史对话」，选一个已有目录的 session。恢复后顶部显示原工作目录，历史消息出现在聊天区，可以直接继续发送。再次选同一个 session 会切回已有面板；选择另一个时原面板、草稿仍保留，可用抽屉切换。

构建方式与 04 相同，在 `apps/android` 运行：

```sh
./gradlew assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug
# 国内版验证（需按 README 提前生成 domestic 运行时）
./gradlew assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug -PwaddleDistribution=domestic
```

本机本轮国际版 APK 留在忽略目录 `artifacts/codex-history/waddle-international-arm64-debug.apk`。新增真实历史恢复测试使用 `-e waddleLiveCodex true` 显式开启；只使用手机已有登录，在专用目录创建测试会话，结束后删除测试目录，不读取或输出真实认证内容。

- 国际版和国内版 ARM64 的 `assembleDebug`、`assembleDebugAndroidTest`、`testDebugUnitTest`、`lintDebug` 均通过；`git diff --check` 通过。

- 其余三项覆盖独立会话审批、历史分页/去重/无 cwd 过滤、历史查询失败不干扰正在运行的任务，以及目录缺失不回落、补回原目录后重试成功。

- 本轮未重复模拟器矩阵、x86_64 或桌面测试（04 已记录此前结果）；GitHub checks 仍待验收者提交后运行，不能把本地结果称为远端 CI 已通过。未 commit、push、建分支或 worktree。

### Fold7 数据与收尾

安装主应用及测试应用均使用 `--user 0 -r`。主应用覆盖安装前后 **3,002 个 home 文件逐文件哈希一致**。测试与人工检查后，`.codex` 以外原有 **34 个文件全部存在、内容完全不变**，真实 `auth.json` 哈希不变；`.codex` 的历史记录、索引、缓存随正常使用更新。

测试应用 `dev.waddle.android.test` 已卸载，主应用没有卸载或清数据，用户 95 没有安装 Waddle。专用测试目录和设备 UI 转储已清理，原 USB 常亮设置恢复为 `0`。主应用已正常打开，并停在刚恢复的用户原有 session；该用户对话只恢复查看，没有发送测试消息。本机测试输出、哈希汇总和 APK 位于忽略目录 `artifacts/codex-history/`，不提交含私有路径的原始清单或历史截图。

### 范围与限制

历史列表显示本机未归档 session，不是云端跨设备同步；已经删除的目录需要用户先恢复，不能自动替换为别处。活动面板仍由终端服务持有，系统结束进程后可再次从历史入口恢复。历史消息显示沿用已有面板最近 300 条可识别消息的上限，完整上下文仍由 Codex session 保存并用于继续聊天；本轮没有增加长对话消息分页。
