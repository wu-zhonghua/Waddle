## 现在的样子

2026-11-22-01 阶段 1 去掉了安装包里的 Codex，终端功能已在模拟器上验收。但构建安卓版要用到的终端原料里还混着两个 Codex 安装包（两种 CPU 架构，共约 188 MB），构建前的校验要求它们必须在。验收时，用户决定这两个包不进仓库：Waddle 要在国内上架，产品和源码都不带 Codex，仓库历史里也不留这么大的文件。所以只提交了终端用的原料，GitHub 上安卓的构建检查因此失败。

同一次 CI 里，安卓设备测试也有 10 项失败：全新的模拟器第一次打开 Waddle 时会弹出通知权限询问，测试没有考虑这一步，后面的操作都被挡住了。真实用户新装后第一次打开也会看到这个询问。详见 01 的验收记录。

## 要做什么

GitHub 上的代码只带构建 Waddle 本体需要的东西。任何人拿到一份刚 clone 下来的干净代码，不需要 Codex 安装包，就能照 README 构建出安卓版并跑通测试，GitHub 上的检查也照常通过。新装后第一次打开时的通知权限询问，不管用户允许还是拒绝，都不影响终端和 AI 入口的使用，测试也要在这种全新环境下照样通过。Codex、Claude Code 以后怎么下载安装，是 2026-11-22-02 的事，这份不管。

## 不做

- 扩展的下载和安装（见 2026-11-22-02）。
- 终端、AI 模型等已有功能的改动（第一次打开时的通知权限询问除外）。
- 改写已经推到 GitHub 的历史提交、强推。
- 阶段 2（AI 一步步做事）。

## 怎样算做好

- GitHub `main` 上找不到 Codex 的安装包；构建 Waddle 的说明和检查也不再要求有它。
- GitHub 上的 Android（构建和设备测试）、Desktop checks 都通过。
- 在一份刚 clone 的干净代码里，按安卓 README 能构建出 APK；装到安卓模拟器上，终端、Bash、Git、curl 照常能用，输入 `codex` 仍然提示没有这个命令。
- 在全新的安卓模拟器上新装 Waddle：第一次打开时询问通知权限，选「允许」或「不允许」，之后终端、文件浏览、AI 入口（没配模型时的引导）都能正常用。
- 安装包大小和 01 阶段 1 验收时差不多（约 23.5 MB），没有变大。
- 01 阶段 1 已经做到的东西（没配 AI 时的引导、AI 设置、多会话、文件浏览和查看）照常能用。
