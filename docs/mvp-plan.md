# Waddle 安卓端 MVP 计划

Waddle 统一覆盖手机与电脑，本计划聚焦安卓端。第一阶段已完成本地实现和 API 35 模拟器验证；第二阶段已跑通 Codex 安装、登录、真实模型任务和会话恢复，审批拒绝、取消及隔离验证仍未完成。优先验证真实终端和手机本地 Codex 两条主线。

## 第一阶段 本地终端原型

使用 Kotlin + Compose 建立 Android 工程，封装独立的终端显示和会话接口，通过 JNI/NDK PTY 启动系统 Shell。默认单终端全屏，提供 Ctrl、Esc、Tab、方向键，加入多会话切换和明确的运行状态。

验收条件：

- 命令实际在 Android 内运行，支持交互输入、Ctrl-C、退出码和窗口 resize。
- ANSI 颜色、光标移动、滚动、中文与软键盘输入正常。
- 旋转或重建 Activity 时不会无意启动重复 Shell。
- 会话结束或被系统终止时正确显示状态；不把日志恢复说成进程恢复。

## 第二阶段 Termux Codex 可行性验证（历史）

当前结果：Android 15 ARM64 + Termux v0.118.3 + Codex 0.170.0 已通过 ChatGPT 设备码登录，实际读取文件、修复拼写并执行检查成功；恢复同一会话后再次检查也通过。但 app-server `command/exec` 的 readOnly/workspaceWrite 写入边界实测未生效，不能据此提供工作区隔离保证；审批拒绝、取消和模型工具的越界阻断仍待验证。详情及复现脚本见[实测记录](research.md#android-本地-codex-实测)。

在可丢弃的测试设备环境检查包仓库，安装可用版本的 Codex 与依赖，并记录 Android、ABI、Termux 来源和 Codex 版本。使用独立测试目录与用户选定的登录方式。

验收条件：

- Codex 能启动并完成登录与一轮请求。
- 能读测试文件、修改一个文件并运行一条无副作用的检查命令。
- 拒绝操作、取消任务、恢复会话按预期工作。
- 记录哪些权限和沙箱能力可用，不默认绕过审批或禁用保护。
- 对比独立 App 的 Termux 桥接与内嵌运行环境成本，再决定正式路径。

## 第三阶段 Waddle 内嵌运行时与 Codex 面板

0.3.0 移除 0.2.0 的 Termux 伴随运行时，改为 Waddle APK 内置 Codex、helper、Bash、Git、rg、curl 和依赖。终端与 Codex 使用同一 home、工作目录和登录；Waddle 通过私有 stdio 管道管理子进程。保留流式消息、设备登录、审批、停止/恢复与原生设置工具。SSH、实体手机验收、全量审批/取消验证和可靠的运行时隔离仍未完成。

增加项目、终端、AI 三种视图。通过版本固定的 app-server 协议接收流式输出、展示工具执行和审批、恢复线程。SSH 后端使用主机密钥校验；远程持续任务需远端会话机制，不能只靠重新连接 Socket。

验收条件：终端与 AI 明确指向同一工作区；UI 标出手机本地与远程位置；断线、取消和错误均有可恢复状态；密钥和令牌不进入日志。

## 第四阶段 安卓设备工具

0.4.0 已实现并在 API 35 模拟器验证亮度与自动模式写入：系统特殊授权、Waddle 开关、每次确认、写后读回。真实 Codex 调用成功；拒绝、关闭开关、缺少权限和过期确认均未产生相应写入。测试后恢复原始设置。下一步是真机验证实际亮度与自动调光效果；这不表示已支持任意系统设置或跨 App 界面控制。

开发时接入 ADB/UI Automator，验证打开自己的 App、读取布局、点击控件、截图与结果检查。独立定义工具接口，例如 get_ui、screenshot、tap、type_text、launch_app；这些是拟定接口，不是已实现能力。

验收条件：动作之前拿到当前设备状态，动作之后重新检查；设备断开时停止执行；同一任务明确绑定设备，避免误操作其他连接设备。

## 第一版暂不承诺

完整任意 Linux 包生态、手机上无网络运行 Codex 模型、无限后台保活、任意 App 私有数据访问、完全自动控制全机。首版目标是可用的安卓终端和可验证的 Codex 工作流。
